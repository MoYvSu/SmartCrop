# ADR-0001：API 与 GPU 推理进程分离

状态：Accepted

日期：2026-09-01

## 决策

V1 在同一 GPU 主机上运行三个独立构件：静态 React 前端、FastAPI API 进程和 Venus worker。API 与 worker 通过 SQLite 任务记录及同一受控数据目录协作；worker 串行领取任务。

连续运行的 worker 由父级看门狗管理。Venus 在子进程中只加载一次；任务运行超过配置时限时，父进程终止该子进程、持久化失败状态并创建新的模型进程。完成写入只接受仍为 `running` 的任务，因此迟到结果不能覆盖超时或手动结果。

## 原因

- CUDA 崩溃或模型 OOM 不应带走 HTTP 服务；
- 单张 4090 的显存不适合未测量的并发推理；
- 进程级终止能兑现 120 秒硬超时，而线程或事后计时不能；
- 同机 SQLite 足以支撑最多 5 个等待任务，部署成本低。

## 后果

- 超时后需要重新加载模型，短期可用容量会下降；
- API 和 worker 必须共享数据库与任务目录；
- 若未来拆分到不同主机，需要以 Redis/对象存储等实现替换运行时包，不改变浏览器契约。
