# ADR-0008：可选翻译的故障隔离与独立时间预算

状态：Accepted

日期：2026-10-17。补充 [ADR-0004](0004-deepseek-report-translation.md)，不改变 DeepSeek 仅接收报告文本的边界。

## 背景

用户要求保留中文翻译，但翻译缺失或不可用时产品仍可运行。此前关闭翻译、运行时翻译异常均可保留原报告；仍有两处缺口：启用 DeepSeek 却缺少密钥时工作进程启动失败；翻译耗时计入推理总上限，可能误杀已经成功完成模型推理的任务。

全新机器默认 `SMARTCROP_REPORT_TRANSLATOR=none`，所以启动 Mock 后端无需密钥。固定使用样例则完全不调用后端。仅凭“页面没有报错”不能判断是否启用了 API、worker 或翻译。

## 决策

1. `deepseek` 缺少/空白密钥，或翻译器初始化配置不合法时，记录固定警告与错误类型并返回未启用状态。不得输出密钥、响应正文或无效配置原文。未知翻译器名称仍视为显式配置错误。
2. 每次翻译的全部重试共用 `SMARTCROP_DEEPSEEK_TIMEOUT_SECONDS` 总预算，默认 12 秒。内部使用可取消的异步 HTTP I/O；同步 `translate(report)` 接口保持不变。取消时关闭响应和连接，不用后台线程继续执行旧翻译。
3. 保留原模型推理时限，默认 120 秒。模型返回后先检查该时限，再在 SQLite 原子记录 `inference_completed_at`；不提前把任务标为成功。
4. 推理后的裁剪制品、可选翻译及最终提交使用单独阶段：有效翻译预算加固定 30 秒的制品/数据库余量；关闭翻译时为 30 秒。无效或非有限翻译预算不会使看门狗无限等待。DeepSeek 自身超过翻译预算时立即回退原报告，不会等到后处理看门狗上限。
5. supervisor 按当前阶段判断硬超时，更新失败状态时在数据库中再次校验阶段与状态，防止旧快照误杀刚进入翻译或刚完成的任务。失去任务处理资格的 worker 不再领取下一任务。
6. 初始 AI 成片使用任务目录内独立的 `crop-initial.jpg/png`，不与手动裁剪的 `crop.jpg/png` 共用。迟到结果只能清理自己的未发布制品，不能覆盖或删除用户已恢复的手动裁剪。
7. 关闭、缺密钥、调用失败或翻译超时均保留模型原报告；翻译成功才标记中文及 DeepSeek 来源。前端仍等待结果整理结束，再看到最终中文或原文报告，任务/API 公共状态不变。

## 数据兼容与部署

内部阶段时间是 SQLite 新增可空列，旧行保持空值并按原推理阶段处理。API/worker 初始化的迁移使用写事务串行化，支持同时启动与重复初始化；不删除旧任务、图片或数据库。

更新后同时重启 API 与 worker，仍按部署流程备份运行数据库。配置继续通过进程环境提供；不增加 `.env` 自动加载，不改动私有配置或密钥。

`--once` 可验证结果返回时的两个阶段时限，但不能强制打断卡死的同步 GPU 或制品函数；强制终止由常驻 supervisor 负责。文件、数据库或模型自身失败仍可能令任务失败，不把该保障描述成任意故障下都能成功。

## 替代方案与取舍

- 直接扩大原推理总时限：会同时放宽 GPU 卡死保护，且仍把可选翻译和推理混在一起，未采用。
- 先宣布英文结果成功，再后台翻译：现有浏览器遇成功即停止查询，容易错过中文，并引入更多结果更新竞态，未采用。
- 用线程包装同步网络请求并等待超时：停止等待不等于停止请求，可能遗留线程或在程序退出时继续等待，未采用。

新增一个内部时间列和少量状态校验，换取清楚的超时语义、兼容现有前端与可测试的迟到结果保护；不引入新服务、训练数据流程或新的产品模块。

## 验证依据

- `tests/test_report_translation.py`：关闭/缺密钥/初始化错误、正常翻译及文本边界、401、临时故障重试、非法响应、总预算、取消请求/响应体和连接关闭。
- `tests/test_worker_timeouts.py`：假时钟模拟接近 120 秒的推理后继续翻译、两个阶段边界、原文降级、旧快照保护、迟到结果与手动成片、失去处理资格后不抢下一任务。
- `tests/test_translation_startup.py`：用真实 CLI 子进程分别启动关闭翻译与启用但缺密钥的 Mock worker，两者都生成可解码的服务器下载制品；不依赖 GPU 或外部 API。
- `tests/test_store.py`：旧数据库新增列、旧任务内容保留和重复初始化。

本轮没有使用真实 DeepSeek 密钥或 GPU；HTTP 故障由测试传输层注入，推理长耗时由假时钟模拟，不宣称已验收真实第三方服务可用性或模型质量。

本机完整 Python 测试 95/95、前端测试 68/68、Ruff、TypeScript 与 Vite 构建均通过。
其中两项 CLI 验收启动了真实 Mock worker 子进程并下载/解码成片；本轮验证未操作远端运行服务或私有配置。
