# ADR-0007：发布目标与人工决策证据进入服务端契约

状态：Accepted

日期：2026-09-06

## 背景

P0.5 第一阶段只在前端生成 schema `1.1` 方案，而服务端制品端点仍输出旧 schema `1.0`，形成两个事实来源。固定比例也只由前端编辑器锁定，API 可以接受与任务比例明显不一致的人工裁剪。

第二、三阶段需要发布模板、自定义比例、选择理由和客观效果信息。如果这些内容只存在于页面状态，下载制品与比赛证据无法可靠复核。

## 决策

- `AnalysisIntent` 增加发布模板和可选自定义比例；旧客户端仍可只提交固定 `aspect_ratio`；
- 自定义比例限制为 `1:10` 至 `10:1`，发布模板与固定比例由契约交叉验证；
- 若原图几何与目标比例无法同时保留宽高至少 2% 的有效裁剪区域，API 在入队前返回明确错误；
- Venus 与 Mock 使用同一解析后的目标比例生成三种候选；
- API 按图像处理层的实际像素取整规则验证最终人工裁剪，允许一像素级误差；
- 选择理由、补充说明和“是否人工调整”保存在任务记录中；
- 系统默认展示候选不等于人工确认，只有用户保存或导出时才记录 `selection_confirmed`；
- 服务端方案端点成为实时任务的唯一方案来源，schema 升级为 `1.2`；
- 方案只记录初始单图报告，不加入终稿复评或候选自动排名；
- 发布模板仅约束比例，不对原分辨率裁剪结果二次缩放。

## 后果

- 前端指标、API 校验和最终方案共享相同的尺寸与比例定义；
- 人工只选择其他候选时不会被误记为手动调整；
- 未确认方案导出为 `selection_mode: unconfirmed`，不会冒充人工决策证据；
- 旧任务 JSON 和只提交固定比例的客户端仍可读取；
- SQLite 增加选择理由和备注字段，但不保存账号、作品历史或用户偏好训练数据；
- 预生成导览在浏览器本地生成等价 schema `1.2` 文件，并显式记录其来源。
- 实时任务方案记录 `provenance: runtime`，预生成导览记录 `provenance: pregenerated`。
