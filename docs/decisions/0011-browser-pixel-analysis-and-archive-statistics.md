# ADR-0011：浏览器像素分析与已归档作品统计

状态：Accepted。日期：2026-10-17。算法版本：`pixel-v1`。

本记录接续 [ADR-0010](0010-demo-account-and-durable-projects.md) 的持久作品边界，采纳不依赖模型的描述性图像分析与归档统计。它不代表摄影质量评分、可靠曝光诊断、个人风格画像或模型能力已经建立。

## 背景

工作台需要让用户理解正在裁剪的画面，摄影洞察需要展示真实作品的统计。现有模型不宜承担可靠的复拍比较、终稿复评或用户偏好推断；亮度、色相、主色与用途等信息可以独立计算，不必强行串入 AI 推理链路。

持久作品已分为可变草稿和固定归档版本。统计若读取正在编辑的草稿，或把同一项目的每次归档都算作新作品，会产生不稳定或重复的结果，因此必须先明确分析对象和统计分母。

## 决策

### 1. 分析当前画面，但不评价好坏

- 工作台从应用内图像读取像素，对当前裁剪区域进行分析；改变裁剪后，立即停止将旧结果展示为新画面的结果，等待约 280 毫秒再计算，避免拖动时反复工作。
- 归档分析读取带固定版本的成片 URL 及其实际尺寸，不用可变草稿的裁剪框去代替已归档成片。
- 结果仅描述当前图像的明暗与颜色分布。图表不判断主体、构图优劣、审美质量或“曝光正确”，也不替代原始 RAW、直方图仪器或专业色彩管理工具。
- 不恢复或解析 EXIF，不据像素猜测快门、光圈、相机或拍摄地点。源图元数据仍遵循上一阶段的剥离策略。

### 2. 固定像素算法与归一化方式

Canvas 请求 sRGB 颜色空间，读取 8 位 RGBA 像素。当前算法直接处理浏览器提供的、经过非线性编码的 sRGB 通道值，并未先做反伽马转换。

- **亮度参考值**：`0.2126 × R + 0.7152 × G + 0.0722 × B`，范围 0—255。它是加权通道值，不是线性相对光度，也不是物理照度。实现采用代数等价形式，避免灰阶阈值处的浮点舍入误差。
- **透明度**：每个像素以 `alpha / 255` 作为可见权重，不在白色或黑色背景上合成后再统计。完全透明像素不贡献亮度、色相和主色；全透明图像的平均亮度为 `null`、主色为空，不伪造成黑图。
- **亮度分布**：按每 8 级划分为 32 个区间，并以可见权重归一化。暗部参考占比采用 `亮度 <= 16`，亮部参考占比采用 `亮度 >= 239`；这些仅是固定区间，不能据此推断欠曝、过曝或细节是否已经丢失。
- **色相分布**：转换为 HSV 后，仅计入 `S >= 0.15` 且 `V >= 0.10` 的有彩像素。色相按每 30° 划分为 12 个区间，以有彩像素的可见权重为分母；另列有彩占比，以全部可见权重为分母。灰阶和极暗画面不能被归入红色，缺少有彩像素时不编造主色相。
- **主色**：先按每通道 4 bit 分桶，将参与聚类的点限制在最多 4096 个；使用固定选种、带权 K-means 迭代及近色合并，最多输出 5 个色块。结果使用确定性排序，不依赖随机初始化；它是小样本近似调色板，不是所有原始像素的精确颜色清单或感知均匀色差分析。
- `pixel-v1` 是分析数据的一部分。聚合拒绝不同算法版本，避免以后改变口径时静默混用旧缓存。

### 3. 小样本、后台计算与受控回退

- 优先使用 `createImageBitmap` 的缩放选项，将基础图像最长边限制为 1280；根据当前裁剪区域再在离屏 Canvas 上采样，最长边不超过 384，小图和小区域不主动放大。传入尺寸必须与所读 URL 对应，不能把缩略图与原图尺寸混用。MDN 说明了该 API 的异步返回及缩放选项：[createImageBitmap](https://developer.mozilla.org/en-US/docs/Web/API/Window/createImageBitmap)。
- Canvas 显式请求 sRGB 并读取 `getImageData`；默认的 8 位 RGBA 数据用于上述计算。旧浏览器可回退普通 Canvas；位图解码不适用时可回退 `Image` 解码并立即缩小保留的基图。颜色空间与像素读取依据见 [MDN：getImageData](https://developer.mozilla.org/en-US/docs/Web/API/CanvasRenderingContext2D/getImageData)。
- 数学计算优先交给独立 Web Worker，即浏览器中的后台计算线程。线程无法启动或失败时，先让出一次页面执行机会，再计算已限制到最长边 384 的样本；不退回在主线程计算原始大图。
- 单张分析有 30 秒总预算；请求或解码不返回时明确失败并继续其余作品。外部取消保持静默；不能真正中断的迟到位图会在返回后释放，不填回缓存。
- 浏览器只在内存中最多保留 2 张已解码基图，按最近使用情况释放旧位图；底层最多缓存 64 份小型分析结果，归档统计另有最多 128 份结果缓存。分析不写入 `localStorage`、IndexedDB 或服务器数据库，刷新后可重算。
- 解码、缩放、色彩转换和浏览器隐私保护可能造成细微差异，不能承诺跨浏览器位级一致或把采样结果当作原图精确检测。

### 4. 只读取受控图像，不扩展数据流向

- 使用同源身份 Cookie、`cache: no-store` 读取应用内项目图像、旧任务图像或固定使用样例；可接受同源临时 Blob，不接受任意跨站图片地址，并拒绝跟随 HTTP 重定向。
- 此阶段的**新增分析计算**在浏览器完成，不新增后端图像分析接口、模型推理调用或第三方图片上送。
- 这不意味着“照片从不上载”：导入与持久作品保存仍沿用现有的服务器上传和保留流程。不得用“浏览器端分析”掩盖既有服务器存储，亦不改变主动删除及临时推理副本的边界。
- 登录失效、网络失败、无法解码和 Canvas 不可用应明确显示；失败不转换为平均亮度 0、空作品数或其他伪造的正常测量。
- 登出、收到账号失效信号以及主动删除作品时，应用清理像素与归档统计缓存，取消在途工作并释放位图。缓存清理递增代次编号，并通过订阅通知分析 Hook；旧解码或旧 Worker 迟到后不能重新填入缓存或写回当前页面。裁剪变化、禁用和卸载也取消旧分析。

### 5. 洞察只统计最新已归档快照

- 每个项目只计一次，使用其最新已归档版本；继续修改但尚未重新归档的草稿不改变统计。固定使用样例不进入作品库统计；历史多版本不当作多份作品。
- 发布用途、横竖幅和裁剪保留面积读取归档当时冻结的 `intent`、成片尺寸与裁剪快照，不读取当前草稿意图或草稿尺寸。时间范围按归档时间选择。
- 全部、近 30 天、近 90 天的筛选不生成模拟数据。图像读取逐张进行，展示总数、完成数和失败项；只有成功读取的像素结果参与颜色聚合，失败作品不能被填成黑图。
- 聚合以**每幅可见作品等权**，不让高分辨率作品因像素多而占更大权重。平均亮度、明暗占比和亮度直方图先在各作品内归一化，再对可见作品求平均。
- 聚合色相先将每幅的色相分布乘以该幅有彩占比，再按有彩贡献归一化；灰阶作品不会虚构色相，也不会被当成整幅红色。全透明作品计入成功读取数量，但不计入可见作品的亮度分母；无可见作品时平均亮度仍为空。
- 聚合主色以各作品的已提取调色板与占比重新聚类，每幅贡献相同总权重，因此是“调色板的近似汇总”，不是把全部原图像素混合后得到的精确分布。
- Mock 推理不影响对真实成片像素和冻结发布意图进行统计；但不能由 Mock 候选、选择结果或占比生成“AI 推荐准确率”“用户偏好已学习”等结论。当前共用演示账号的数据也不能包装成某个访客的个人画像。

## 替代方案与取舍

直接依赖模型生成图表实现较快，但会把不可验证的文本结论当作测量，本阶段不采用。后端统一分析便于持久缓存与跨设备复用，却增加服务端计算、结果存储和版本迁移负担；当前小规模受控演示采用浏览器计算即可。

全分辨率统计或专业感知色彩算法可能更精细，但会提高解码、内存和交互成本。小样本、确定性聚类的取舍是可交互、可解释且不依赖模型，代价是近似色块、细小区域误差和浏览器差异，必须在界面保持说明。

累计所有历史版本能够展示创作过程，却会让频繁归档者被重复计数；当前先采用“每项目最新成片一次”的清楚口径。版本轨迹、拍摄参数、主动学习和个人画像属于以后单独决策的能力，不在本次范围。
