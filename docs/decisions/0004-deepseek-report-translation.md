# ADR-0004：使用 DeepSeek 翻译结构化报告

状态：Accepted

日期：2026-09-05

## 背景

真实 30 图回归表明，Venus 使用中文提示词时仍倾向输出英文；直接使用英文提示词的结构化
报告链路更稳定。本地 CPU 小型翻译模型的术语质量不足，而 RTX 4090 的剩余显存不适合再
常驻一个翻译模型。

## 决策

Venus 继续用英文提示词直接查看图片并生成五字段英文 JSON 报告。worker 校验报告后，调用
DeepSeek 的 OpenAI 兼容接口，将字段值翻译为简体中文，并再次通过 `Report` 契约校验。

- 只发送英文报告文本，不发送图片、文件路径、访问码、任务 ID 或其他用户元数据；
- 使用 `deepseek-v4-flash`，关闭思考模式并要求 JSON 输出；
- 翻译器在 worker 进程内运行，API 进程不调用第三方接口；
- 失败时保留英文原文并完成裁剪任务，前端明确标记英文降级；
- 日志只记录提供方、模型、耗时和错误类型，不记录密钥或报告正文。

## 后果

用户通常获得中文报告，GPU 显存不增加；代价是报告文本会发给外部服务，并产生网络延迟和
API 成本。翻译被限定为非关键增强，因此第三方故障不会破坏已经成功的裁剪结果。
