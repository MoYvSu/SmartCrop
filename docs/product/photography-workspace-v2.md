# SmartCrop 摄影工作室 V2：产品范围与数据边界

状态：第四阶段已接入账号创作偏好、新建自动采用与作品辅助线恢复；拍摄参数仍待实现。
日期：2026-10-17。

## 1. 定位与设计目标

由单次裁剪流程扩展为宽屏 Web 摄影工作室，围绕创作、作品管理和摄影复盘组织功能。
优先保证桌面浏览器的信息密度、图像查看空间和跨页连续性，窄屏维持基本可访问，不承诺原生 App。
延续现有摄影编辑室视觉语言；丰富来自真实图片、有效图表及作品记录，不靠堆叠装饰卡片。
继续用于授权研究、内部展示及受控非商业演示；本稿不扩大模型与素材的授权范围。
像素分析、手动精修、可选 Venus、报告翻译和账号档案分别承担明确职责。
Venus 是可按需调用的构图工具，不统领导航、像素计算、作品管理或用户偏好。

## 2. 相对既有版本的设计变更

| 既有交付边界 | 本稿拟议变化 |
| --- | --- |
| 上传、等待、结果构成单条主流程 | 增加五页导航，以作品及持续创作为组织单位 |
| 以模型分析进入结果页 | 无 AI 也可开始像素分析与手动精修，AI 由用户按需调用 |
| 共享访问码控制入口，没有账号历史 | 预置一个真实演示账号，形成共用作品、洞察与档案 |
| 上传及结果属于一小时临时任务 | 新增独立草稿和归档作品，生命周期另行定义 |
| 选择依据只随临时任务暂存 | 用户确认成片后保存创作记录，按来源形成作品统计 |

以上是新设计范围，不表示旧版本已经具有这些能力；旧任务仍执行已实施的一小时规则。
已有的人机协同、候选不排名、报告解释初始分析及翻译失败保留原文等边界继续保留。

## 3. 宽屏导航与五个页面

一级导航固定使用以下名称，不另设与其重复的“历史”“个人中心”或“数据中心”入口。

| 页面 | 主要任务 | 内容边界 |
| --- | --- | --- |
| 创作概览 | 继续草稿或开始创作，了解工作室近况 | 新建入口、最近草稿、近期成片及少量带样本数的摘要；不复制完整洞察页 |
| 构图工作台 | 观察照片、精修取景并确认成片 | 原图与预览、目标比例、像素分析、可选 AI 候选、说明与归档操作 |
| 我的作品 | 查找、查看、继续编辑和删除作品 | 明确区分草稿与已归档成片，支持查看保存时的坐标、说明及来源 |
| 摄影洞察 | 复盘已确认作品的客观分布及选择习惯 | 色彩、明暗、裁剪及可用拍摄参数统计；标明范围、样本数和缺失数据 |
| 摄影档案 | 查看演示身份并编辑摄影偏好 | 账号说明、常用用途、比例及偏好；统计推断只能是可纠正的建议 |

导航不是新的工作流门槛：可直接开始创作，也可从作品或草稿回到同一工作台。
切换页面应保留已保存草稿，并清楚反馈尚未完成的保存，不静默丢弃调整。
五页空态均提供有意义的下一步；历史不足时不用虚构作品或百分比填满页面。
Venus 不可用时，五页导航、像素分析、手动精修和既有作品仍可正常使用。

## 4. 模块职责与降级

- 像素分析：浏览器读取图片，计算亮度/RGB、色相、主色及亮暗区域；无需模型或翻译服务。
- 手动精修：处理裁剪比例、移动、缩放、辅助线、预览及成片输出，不要求先成功生成 AI 报告。
- 可选 Venus：用户主动请求后生成构图候选及初始画面分析；失败时保留手动工作区和已有草稿。
- 可选翻译：只翻译已有报告文本；缺配置、失败或超时显示原文，不改变其他模块的可用性。
- 作品与档案：管理已保存记录、汇总和用户主动设置；不通过 Venus 决定账号状态或数据归属。

AI、翻译与本地统计均标明来源和状态，未调用、运行中、不可用不能冒充完成。
修改裁剪后可重新计算客观图表；旧 AI 报告仍标注它对应初始分析，不伪装为终稿复评。
用户可以从纯手动流程完成归档与下载；图像或文件处理本身失败仍须明确报告。

## 5. 创作与记录闭环

```text
选择照片 → 自动保存草稿 → 像素分析 / 手动精修 / 可选 AI
         → 明确确认成片并归档 → 我的作品 → 摄影洞察与可编辑偏好
```

草稿用于恢复尚未结束的创作；更新草稿不等于确认成片，也不等于加入作品统计。
“确认成片并归档”是单独、明确的用户动作，成功后作品才进入归档列表及作品数量。
保存失败时保留当前调整并允许重试；只有图像及相关记录保存成功后才显示归档完成。
从归档作品继续精修应重新形成待确认草稿，明确展示未归档调整与已有成片的区别。
重复保存同一草稿、反复点击下载或更新同一作品，不应虚增作品数或偏好次数。
用户可以确认默认构图，但默认展示、接受默认值和单纯下载均不算主动选择偏好的证据。
显式切换方向、手动调整、填写选择依据等行为应与默认接受区分，并保留其含义。

## 6. 一个真实演示账号

仅预置一个可实际登录的演示账号；不开放注册，不增加社交登录、角色后台或生产级账号管理。
本版采用受控共享演示：使用该账号的人共用作品、草稿、统计和档案，不承诺个人隔离。
登录及相关页面应说明“演示账号的数据由参与演示的人共同使用”，避免“仅自己可见”的暗示。
演示图片使用已授权素材；账号凭据、图片及运行数据不写入 Git。
登录状态由服务端会话维持；作品的读取、修改和下载在服务端核验身份与归属，不能仅前端隐藏。
现有共享访问码不等于账号体系；后续若保留为部署门禁，也不能绕过账号会话检查。
退出登录应结束当前会话，但不自动删除该共享账号的归档作品或假装重置全部历史。
公开多访客隔离、不同人员独立作品库及跨用户权限体系不在本版范围。

## 7. 临时任务、草稿与归档作品

| 数据类别 | 当前保留规则 | 说明 |
| --- | --- | --- |
| 现有临时分析任务 | 继续保留一小时 | 已实施规则；不因本稿自动延长，也不能直接充当新作品库 |
| 新工作室草稿 | 保留至用户主动删除 | 第二阶段保守实现，不启用此前提议的 24 小时自动删除，避免未完成作品丢失 |
| 用户确认的归档作品 | 保留至用户主动删除 | 已独立保存源图、编辑快照、成片和版本；重置共享数据需另行明确维护授权 |
| 固定示例资源 | 受控维护，不随访客创作改变 | 使用授权素材并持续标注固定来源 |

持久作品必需的照片、成片与编辑快照，以及实际存在的可选报告和说明，必须成为独立、可验证的保存集合。
未运行或失败的 AI 报告、翻译和未填写的说明可为空，不是归档前置条件。
不得只引用一小时后会清理的任务图片或报告地址，否则作品列表会保留失效记录。
草稿所需原图同样要有与草稿期限一致的保存来源，不能依赖早已过期的任务。
临时任务清理不得误删已归档作品；只有确认归档成功，才将其视为可持续恢复的作品。
删除作品时同步处理其专属文件、选择记录及统计贡献；仍被其他记录使用的资源不得误删。
重置演示数据是明确的维护动作，恢复受控示例，不冒充用户个人退出或普通页面刷新。
上述规则只适用于新工作室项目；旧版临时任务不自动迁移，已清理的照片不能恢复。删除项目会删除其专属持久资源，并阻断关联任务访问；旧分析任务的临时副本仍由一小时清理链路处理，不承诺点击删除即擦除所有副本或备份。

## 8. 原图信息与像素指标边界

持久图像仅保留规范化像素，全部 EXIF/附加元数据均被剥离，包含 GPS 和设备序列号；因此当前不展示相机参数，不假装已经提取。第三阶段的像素分析也不恢复或猜测这些字段。
后续如接入设备、镜头、快门、光圈、ISO 等白名单字段，需单独实现隐私筛选与测试；缺失时显示“未记录”，不通过模型猜测。
如未来另行提供未经处理的原始文件备份，需要先重新明确元数据范围；本稿不默认增加该能力。
透明像素、低饱和像素、色彩空间及采样方式须定义一致口径；黑白图不强行给出有彩色色相结论。
裁剪前后图表只解释保留内容的变化；亮度、色相、边缘或保留面积不能转换为审美分数或优劣排名。
亮暗阈值只描述当前图像接近端点的像素；不能宣称由此测得 RAW 曝光正确性或传感器动态范围。

## 9. 统计、来源与偏好

项目来源（用户创作／固定示例）与 AI 运行方式（Venus／Mock 模拟／未运行）分别标识；固定内容不能伪装成该账号曾实际创作的历史。
真实作品统计默认排除固定示例；用户照片即使未运行 AI 或试用过 Mock，其客观像素、用途及已有 EXIF 仍可计入已归档作品统计。
Mock 生成的方向、报告及其接受记录不作为真实 AI 选择或偏好证据；演示图表若展示固定样例，应注明“示例统计”。
作品数量、构图方向及拍摄参数统计都给出有效样本数；缺失 EXIF 不能记为零或默认设备。
草稿不计入成片统计；删除作品后更新相关图表和摘要，不继续使用已删除作品推断偏好。
主动选择与默认接受分别处理；缺少有效行为时显示证据不足，不自动生成强偏好结论。
摄影档案中的偏好由用户编辑、确认或清除；算法建议标注来源，不覆盖主动设置。
共享账号的画像只代表演示账号混合记录，不宣称它刻画任何一位访客的个人习惯或性格。

## 10. 评审与后续实现边界

本版不增加 Agent、主动学习、训练数据捐赠、复拍跨图比较、终稿复评或自动候选美学排名。
不扩大为生产级身份管理、多租户系统、原生移动应用或全套图片后期软件。
实现顺序建议为五页结构与单账号、独立草稿/归档闭环、客观像素图表、作品汇总与可编辑档案。
验收应覆盖无模型创作、翻译降级、草稿恢复、临时任务过期后访问归档作品、删除后统计更新。
还应核对共享账号提示、来源隔离、EXIF 缺失与敏感元数据处理，不以静态页面截图代替功能验收。

## 11. 待确认事项

1. 若未来需要自动草稿清理，须重新确认保留期限及提示方式；当前采用保留至主动删除，不实施 24 小时规则。
2. 是否公开试用：当前按受控共享账号设计；如需陌生访客并发试用，应先重新确定数据隔离与保存边界。
