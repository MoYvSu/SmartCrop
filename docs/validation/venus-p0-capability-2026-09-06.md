## 结论

当前 Venus 部署在本轮完成了全部单图裁剪坐标生成，并且产品侧可以把候选严格适配到目标比例；但它还不能稳定产出三种有明显区别的构图方案，终稿复评的结构化输出也有较高失败率。因此：

- 保持 `SMARTCROP_P0_CAPABILITIES_VERIFIED=false`；
- 不宣称模型已经具备稳定的“方案比较”或“跨图构图优劣判断”能力；
- 当前 P0 只能作为真实模型未验收的实验链路，不作为能力演示结论。

## 三策略差异性

策略提示词要求：`subject` 比 `balanced` 更紧，`story` 比 `balanced` 更宽并保留环境。实测面积关系如下：

| 关系 | 符合样例数 |
| --- | ---: |
| `subject` 面积小于 `balanced` | 22 / 30 |
| `story` 面积大于 `balanced` | 19 / 30 |
| `subject` 面积小于 `story` | 22 / 30 |
| 平均 `subject / balanced` 面积比 | 0.87 |
| 平均 `story / balanced` 面积比 | 1.05 |

整体均值方向符合提示词，但逐图一致性不足。每张图最相似候选对的平均 IoU 为 0.9141；以下 8 张至少有一对候选 IoU 不低于 0.98：

| 样例 | 最相似策略对 | IoU |
| --- | --- | ---: |
| `flms-06` | `story` / `subject` | 0.9990 |
| `flms-11` | `balanced` / `subject` | 0.9830 |
| `flms-13` | `balanced` / `story` | 0.9980 |
| `flms-14` | `story` / `subject` | 1.0000 |
| `flms-18` | 三对均相同 | 1.0000 |
| `flms-21` | `balanced` / `story` | 0.9990 |
| `flms-22` | `balanced` / `subject` | 0.9801 |
| `flms-30` | `balanced` / `subject` | 0.9945 |

这表明当前探针原先只检查“四舍五入后完全重复”过于宽松；即使结构检查通过，用户也可能看到视觉上基本相同的候选。

## 人工抽查

抽查了 `flms-02`、`flms-03`、`flms-05`、`flms-13`、`flms-20`、`flms-30` 的原图、候选坐标及初次/终稿报告。

- 可见内容真实性：多数报告能识别主要对象和场景。例如海滩独木舟、窗洞中的塔楼、日落倒影、人物手势等描述与原图相符；没有发现引用前序对话或直接声称比较了两张图片。
- 评价具体性：大量语句停留在“构图平衡”“负空间增强”“增强互动感”等通用摄影措辞，缺少与另外两个候选的明确、可核对差异。
- 显著内容保护：`flms-30` 是明显反例。原图主体是顶部带金色雕像的纪念柱，16:9 的三个候选都裁掉了顶部雕像；`balanced` 与 `subject` 几乎相同，终稿报告仍以泛化措辞评价柱体、细节和负空间，没有指出关键主体被截断。
- 策略一致性：`flms-13` 的 `balanced` 与 `story` IoU 为 0.998，`flms-06` 的 `subject` 与 `story` IoU 为 0.999，难以向用户解释为不同构图决策。

人工抽查只能说明“部分报告与单张成片可见内容一致”，不能证明模型具备可靠的跨候选排序能力。当前实现本身也没有把多张候选同时输入模型进行成对或列表排序；它是三次独立提示生成候选，再对默认成片做一次单图复评。

## 建议的下一步

1. **先修复复评稳定性。** 为失败重试保留结构化失败类别和响应长度；收紧复评提示或增加受控 JSON 修复，使同一固定集的复评成功率达到验收阈值。
2. **升级差异性门禁。** 将“候选完全不相同”改为成对 IoU 门禁，并记录每张图的策略面积关系；建议先以任意候选对 `IoU >= 0.98` 记为重复风险。
3. **单独设计真正的比较验证。** 如果产品要声称“哪个候选更好”，需要让模型同时观察多个候选并输出结构化排序、逐项理由与可见证据，再用盲评偏好数据验证；现有三次独立生成不能支持该声明。
4. **加入显著主体保留检查。** 对人物头部、纪念物顶部、文字或商品边缘等高风险裁断建立人工标签或检测门禁，避免像 `flms-30` 这样的形式合法但语义失败。
5. **保持能力开关关闭。** 修复后应在同一 30 张固定集重复运行至少两轮，并完成全量人工复核，再讨论是否将状态从 `unverified` 改为 `verified`。
